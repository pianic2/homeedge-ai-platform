## Thermal observation

Maximum CPU temperature observed during the 300-second bounded CPU stress was **84.724 °C**.

Raspberry Pi documentation states that the Arm cores are progressively throttled in the 80–85 °C range, with thermal control reducing frequency as the device approaches the thermal limit. Therefore this run is strongly consistent with a **thermal throttle event**.

The v5 summary did not expose the final `vcgencmd get_throttled` bitmask separately from the combined `no_pi_throttle_or_undervoltage` gate. For strict evidence hygiene, the exact cause is not promoted from correlation to confirmed bit-level classification in this record.

The harness has subsequently been remediated to sample/decode `get_throttled` during stress and to separate undervoltage from frequency-cap/throttle diagnostics.

## Disposition

This run does **not** reject:

- Raspberry Pi 4 Model B as the reference candidate;
- the owned A1 microSD;
- Raspberry Pi OS Lite 64-bit;

- storage integrity or basic resource stability.

It rejects only the tested **passive cooling configuration** (`case + heatsink, no fan`) for the current bounded 300-second stress acceptance envelope.

Next candidate configuration: same hardware/software/storage/PSU, with improved airflow / fan enabled and exact cooling setup recorded.

Because `vcgencmd` historical flags persist for the current boot, the next acceptance run must start after a reboot with a clean pre-flight throttle history.
